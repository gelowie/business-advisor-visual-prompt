# T8 — Complex Multi-Problem

**Use when:** Two or more problems that depend on each other, where changing the answer to one would change the question for another. No hard clock of days or weeks (use T9 for that).
**Level:** Complex
**Fields marked with a bracket** are filled from what the user said. A field with no user data is removed and, if it matters, listed under *Not provided yet* (see `assets/output-format.md`).

## Template

```text
In my words:
"[...]"

Business:
- Type: [service-based | digital product/SaaS | physical product/e-commerce | local brick-and-mortar]
- Industry: [...]
- Stage: [startup | growth | established | turnaround]
- Jurisdiction: [country, state or province]   (keep when any problem involves law, tax, employment or fundraising)

Known (please don't re-ask):
- [How long the problems have been present]

Problems:
1. [Domain]: [the problem, with what has been tried]
2. [Domain]: [the problem, with what has been tried]
3. [Domain]: [the problem, with what has been tried, if any]

Suspected links (my hypotheses, not conclusions):
- I think [problem A] affects [problem B] because [reason].

Not provided yet:
- [...]

Assumptions to verify (not confirmed):
- [...]

Research context (unverified unless sourced):
- [...]

Constraints:
- Budget: [range]
- Timeline: [when results are needed]
- Resources: [team, tools, outside support]

Outcome I want:
Test whether these problems really depend on each other. If they do, tell me which to address first, why, and what to avoid doing out of order. If some are independent, say so and treat them separately.
```

## Rationale cue

State the user's suspected links as hypotheses and ask the advisor to test them, so it decides whether to coordinate or separate the problems.
